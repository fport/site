# Gardens

A garden is a whiteboard of notes, served at `/garden/<id>`. `ai` and `talks`
exist today; `system-design` and `backend` slot in the same way. Notes are MDX
files in the repo — there is no database and no editor, only files, git and a
build.

## Anatomy

```
src/garden/
  types.ts              shared types + helpers (placeNotes, findNote)
  index.ts              registry of every garden
  ai.ts                 the AI garden: metadata, clusters, note list
  ai.layout.ts          generated card placement (x, y, w, h per slug)
  talks.ts              the Talks & Resources garden
  talks.layout.ts
  notes/<id>/*.mdx      the notes themselves

src/components/garden/
  canvas.tsx            the whiteboard (client): pan, zoom, drag, search
  note-card.tsx         a card, in canvas or list mode
  note-reader.tsx       full-size overlay
  garden-index.tsx      left rail: search + jump-to-note
  cluster-regions.tsx   dashed regions, sized from their members
  edges.tsx             arrows between linked notes
  author-toolbar.tsx    author mode controls
  use-viewport.ts       pan/zoom maths
  primitives.tsx        <Schema> <Box> <Arrow> <Pipeline> <Stack> …
  mermaid.tsx           lazy, theme-aware mermaid renderer

src/app/garden/
  page.tsx              index of every garden
  [garden]/page.tsx     renders MDX on the server, hands elements to the canvas
  [garden]/[slug]/      permalink, normal reading page
```

MDX is rendered **on the server** and passed to the client canvas as React
elements, so note content never ships as client JavaScript. Only the canvas
mechanics are client code.

## Adding a note

1. Write `src/garden/notes/<id>/my-note.mdx`.
2. Add an entry to `notes` in `src/garden/<id>.ts` — `slug`, `title`, `summary`,
   `kind`, `status`, `updated`, and optionally `cluster`, `tags`, `accent`,
   `links`.
3. Place it (below).

`links` draws an arrow from this note to another slug. `cluster` puts it inside
a dashed region, which resizes itself around whatever belongs to it.

## Placing cards (author mode)

Open `/garden/<id>?edit=1`:

- drag a card by its **header**, resize from the **bottom-right corner**
- movement snaps to 8px; hold <kbd>Shift</kbd> for free placement
- changes persist to `localStorage` while you work
- **copy layout** puts the full contents of `src/garden/<id>.layout.ts` on the
  clipboard — paste it over that file and commit
- **reset** throws the draft away

Author mode is a local convenience, not an admin panel: it writes nothing to a
server, and `?edit=1` gives a visitor no access to anything they did not
already have.

## Writing schemas

Every primitive is registered globally in `mdx-components.tsx`, so notes use
them without importing:

| Primitive | For |
| --- | --- |
| `<Schema title>` | framed drawing surface with a faint grid |
| `<Pipeline steps={['A\|caption', 'B']} />` | `A → B → C` in one line |
| `<Stack layers={[{label, sub, accent}]} />` | layered architecture |
| `<Box sub accent dashed>` / `<Arrow dir label>` | hand-built diagrams |
| `<Row>` / `<Col>` | arranging the above |
| `<Meter label value max unit>` | budgets, ratios, deltas |
| `<Callout type>` / `<Sticky accent>` | asides and post-its |
| ` ```mermaid ` fence | flowcharts, sequence diagrams |

Mermaid is lazy — it loads only when a diagram scrolls into view, so pages
without one never pay for it.

Accents: `amber` `lime` `sky` `rose` `violet` `slate`.

**Markdown tables do not work.** `next.config.ts` sets `experimental.mdxRs`,
and the Rust MDX compiler has no GFM extensions — a `| a | b |` table renders
as literal pipes. Use the `<Table data={{ headers, rows }} />` component that
`mdx-components.tsx` already provides. (Dropping `mdxRs` would allow
`remark-gfm`, at the cost of a slower build.)

## Adding a new garden

1. `src/garden/system-design.ts` + `src/garden/system-design.layout.ts`, same
   shape as the existing pairs, with `path: '/garden/system-design'`.
2. Add it to `gardens` in `src/garden/index.ts`.

That is the whole job. `/garden/system-design` and its note permalinks are
generated by the existing `[garden]` routes, and the new garden appears on
`/garden` automatically. The canvas takes `garden` and `notes` as props and
knows nothing about which garden it is showing.

## Layout note

`src/app/layout.tsx` is a bare shell (html/body/theme). The reading pages live
under the `(site)` route group and get `SiteShell` — the 60ch measure, the
footer and the chat bubble. The canvas deliberately skips it so it can run full
bleed; the garden index and note permalinks opt back in.

Old URLs (`/ai-garden`, `/ai-garden/:slug`, `/paper/talks`) redirect
permanently from `next.config.ts`.
