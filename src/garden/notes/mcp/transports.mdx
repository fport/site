## Why the shift away from SSE

The original remote transport held a long-lived server-sent-events stream open
so the server could push requests back. That made every connection **sticky** —
you could not put a plain load balancer in front of it, and a dropped stream
lost the session.

<Callout type="gotcha" title="If you are reading older material">
  A lot of MCP writing still describes HTTP+SSE and a session id as the normal
  remote setup. That is the old shape. New remote servers should be stateless
  over Streamable HTTP.
</Callout>

<Sticky accent="sky">
  stdio is not a lesser transport — for anything that touches the local
  filesystem or local credentials it is the correct one, and the simplest.
</Sticky>
