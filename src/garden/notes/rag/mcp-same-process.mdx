## Design choices

- **Same process, same retriever.** No stdio sidecar loading the embedding
  model twice; blocking work (embedding, Milvus, disk) runs in threads so the
  MCP session's event loop keeps flowing.
- **Output is data, not instructions.** Code returned to the agent is wrapped
  as untrusted content.
- **Signals travel with the hits.** Weak-match band, `DOC` label, "N
  candidates dropped", last index time per repo.
- **`read_code` reads only indexed files.** The path must be in the manifest —
  so the agent cannot read `node_modules` or `.env`, and cannot be told "that
  file exists" when it does not. If the file on disk no longer matches the
  indexed hash, the slice comes back flagged `stale`.
